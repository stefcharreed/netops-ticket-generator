# Normalized log-format registry

Generated by `scripts/import_registry.py SRC_DIR registry` from source registry YAMLs (not included in
this repo), so the registry can't be regenerated from this checkout. Change it with hand-reviewed PRs to
`registry/*.yaml`: edit with care and keep fields as documented below. Re-running the importer on a source
set replaces the files, including any hand edits.
Loaded by `packetgen.registry.load_registry`.

## Entry fields
`id`, `vendor`, `header_style`, `severity` (int or null), `message`, `placeholders`, `example`,
`source_url`, `verified`, `demoted_reason`.

- `message` starts at the vendor token (`%FAC-SEV-MNEM:`, `%ASA-...`) or the `program[pid]:` tag.
  The syslog header is added per device by `header_style`.
- `{name}` is a placeholder; repeats get `_2`, `_3`. An inline `{A|B}` becomes `{choice_N}`.
  `[[ ... ]]` is an optional section, dropped when all its fields are missing or empty.
- `placeholders` maps name to a regex. No regex means free text, `.*?`.
- `verified: false` with a `demoted_reason` means the source claimed verified, but the entry's own example
  failed its own pattern. Entries unverified at the source have `demoted_reason: null`.
  Only `verified: true` entries are usable unless the spec sets `meta.allow_unverified`.

## id prefix to header_style
ios: IOS, C9800 | nxos: NXOS | asa: ASA, FTD | bsd: ISE, ISCDHCPD, JUNOS, CHRONY, NTPD, UNBOUND |
meraki: MERAKI | null (unsupported): PANOS, FGT, ARUBA, KEA, FREERADIUS, BIND, WINDHCP, WINDNS, IEEE80211, EAPOL

## Validation status
Fixture-tested only: every verified example matches its own pattern. Nothing here is validated against real gear.
